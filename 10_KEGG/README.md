# 🧬 KAAS → KEGG Pathway Analyzer

**Automated fungal protein KO assignment, KEGG annotation, pathway mapping and functional summarization**

A local Python/Streamlit application developed for functional annotation of fungal protein datasets using results generated by the **KEGG Automatic Annotation Server (KAAS)**.

The application converts completed KAAS protein-to-KO assignments into structured **KO, EC, enzyme, pathway and protein-level annotation tables**, with Excel export and KEGG response caching for efficient and reproducible analysis.

# 1. Overview

The KAAS → KEGG Pathway Analyzer is designed to provide a convenient local workflow for researchers who have:

1. A protein FASTA file
2. A completed KAAS annotation result

The workflow uses KAAS for protein ortholog/KO assignment and then retrieves additional information from KEGG to generate structured functional annotation results.

KAAS performs functional annotation by comparing query sequences against the manually curated KEGG GENES database and provides KO assignments and automatically generated KEGG pathway information.

---

# 2. Complete Workflow

The recommended workflow is:

```text
Protein FASTA
      ↓
KEGG KAAS
      ↓
KAAS protein annotation
      ↓
Completed KAAS result
      ↓
KAAS result URL
      ↓
KAAS → KEGG Pathway Analyzer
      ↓
Protein ID → KO ID
      ↓
FASTA–KAAS ID validation
      ↓
Unique KO identification
      ↓
KEGG information retrieval
      ↓
KO / EC / Enzyme / Pathway annotation
      ↓
Protein-level mapping
      ↓
Summary tables
      ↓
Excel results workbook
```

---

# 3. Step 1 — Prepare the Protein FASTA

Prepare the protein sequences in standard multi-FASTA format.

Example:

```text
>protein_001
MSTAVKLA...
>protein_002
MNVLSPTA...
>protein_003
MKKLAV...
```

Protein identifiers should be unique.

KAAS documentation specifies that amino-acid query sequences should normally be supplied in multi-FASTA format with unique IDs.

---

# 4. Step 2 — Submit the FASTA to KAAS

Open the official KEGG Automatic Annotation Server:

**KAAS:**
https://www.genome.jp/tools/kaas/

The KAAS job request page is provided by GenomeNet/KEGG.

Upload the prepared protein FASTA file.

Provide:

* Query name
* E-mail address
* Appropriate search program
* Appropriate KEGG GENES dataset
* Appropriate assignment method

KAAS supports different assignment approaches including BBH and SBH, depending on the type of dataset and analysis.

### Important

Use the **same original protein FASTA** later in this application.

The FASTA is used to validate that the protein IDs in the KAAS result correspond to the original protein dataset.

---

# 5. Step 3 — Wait for KAAS Completion

After submitting the KAAS job, wait until the annotation is completed.

KAAS provides the result access information through the e-mail address supplied during submission.

The completed result contains protein-to-KO assignments and pathway-related annotation.

---

# 6. Step 4 — Copy the Completed KAAS Result URL

After the KAAS job has completed, copy the **completed KAAS result URL**.

This URL is required by the KAAS → KEGG Pathway Analyzer.

Example:

```text
https://www.genome.jp/kaas-bin/kaas_main?id=XXXXXXXX
```

Do not use the initial KAAS submission page as the analysis input.

Use the URL corresponding to the **completed KAAS result**.

---

# 7. Step 5 — Start the KAAS → KEGG Pathway Analyzer

The application runs locally using Python and Streamlit.

The user provides:

### Required

**1. Completed KAAS result URL**

### Recommended

**2. Original protein FASTA**

The original FASTA allows the application to perform protein-ID validation against the KAAS assignments.

---

# 8. Running the Application in Ubuntu / WSL

The application can be run locally in Ubuntu/WSL.

## Activate the environment

```bash
source ~/miniconda3/etc/profile.d/conda.sh
conda activate kaas_github_test
```

## Install requirements

From the application directory:

```bash
pip install -r requirements.txt
```

## Start the application

```bash
./run_app.sh
```

Alternatively:

```bash
streamlit run app.py
```

The application will provide a local address such as:

```text
http://localhost:8501
```

Open this address in a web browser.

---

# 9. Application Inputs

## Input 1 — Completed KAAS Result URL

Paste the URL of the completed KAAS result.

The application retrieves the KAAS result and extracts the protein-to-KO assignments.

## Input 2 — Original Protein FASTA

Upload or provide the original protein FASTA used for the KAAS analysis.

The application uses the FASTA to validate protein identifiers and determine whether KAAS assignments correspond to proteins in the original dataset.

---

# 10. Testing Mode

For initial testing, the application provides a testing option that can process a limited number of proteins.

This is useful for:

* Testing the KAAS URL
* Checking FASTA compatibility
* Checking protein-ID matching
* Confirming KEGG retrieval
* Verifying Excel output generation

After successful testing, the complete FASTA can be processed using **FULL MODE**.

---

# 11. Full Analysis Mode

In **FULL MODE**, the complete uploaded protein FASTA is analyzed.

The workflow performs:

1. KAAS result retrieval
2. KAAS result parsing
3. Protein ID extraction
4. KO assignment extraction
5. FASTA ID validation
6. Identification of proteins with KO assignments
7. Identification of proteins without KO assignments
8. Identification of unique KO IDs
9. KEGG KO information retrieval
10. EC/enzyme annotation retrieval
11. KEGG pathway retrieval
12. Protein-to-KO mapping
13. Protein-to-pathway mapping
14. Summary generation
15. Excel workbook generation

---

# 14. KEGG Data Retrieval and Caching

The application retrieves additional KO, enzyme and pathway information from KEGG.

KEGG provides databases including:

* PATHWAY
* BRITE
* KO
* GENES
* REACTION
* ENZYME

and associated analysis resources.

The application maintains a local cache of retrieved KEGG responses.

Caching helps:

* Avoid unnecessary repeated requests
* Resume interrupted analyses
* Reduce repeated KEGG queries
* Improve reproducibility
* Speed up subsequent analyses

Users should respect the applicable KEGG access policies and request-rate limitations. KEGG states that academic users providing services using KEGG should follow its applicable licensing/access requirements.
